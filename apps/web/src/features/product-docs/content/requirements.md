# 需求输入、规则确认与 AI 修复

## 适用场景

你要把自然语言需求整理成平台可追踪的需求规则，并在生成可行性分析或需求模型前处理质量提示、待确认项和 AI 修复建议。

## 入口位置

- 项目工作台左侧“系统需求”。
- 系统需求页顶部的需求文本输入区。
- 规则列表中的“采纳自动补齐”“忽略自动补齐”和“智能修复”按钮。

![需求规则确认与 AI 修复局部截图](/help/images/docs-requirement-ai-repair.png)

## 前置条件

项目需要有可用模型配置。需求文本至少要说明角色、业务目标、主要流程、异常情况和数据约束。

## 操作步骤

1. 在需求输入区粘贴“图书馆预约系统”需求。
2. 点击生成需求规则。
3. 查看规则分类：功能需求、业务规则、数据需求、异常处理、非功能需求。
4. 对质量提示逐条处理：缺字段时采纳 AI 自动补齐，误判时忽略。
5. 对单条规则使用 AI 修复时，比较修复前后文本和修复理由。
6. 所有待确认项处理完后，再进入可行性分析或需求模型。

## 输入示例

```text
学生可以查询空闲座位并提交预约。预约必须校验登录状态、日期、时间段和重复预约。
管理员可以维护座位，查看预约记录，并在学生未到场时取消预约。
系统需要在预约成功和取消时发送通知。
```

## 预期输出

| 输出 | 说明 |
| --- | --- |
| 需求规则 | 下游可行性分析、UML、设计、测试和说明书的共同输入 |
| 质量提示 | 标记缺少角色、数据、异常、边界条件的风险 |
| AI 修复候选 | 给出修复后的规则文本、理由和阻塞原因 |
| 需求基线 | 记录已确认规则和需求文本版本 |

## 映射关系

| 需求规则 | 映射到 |
| --- | --- |
| “学生提交预约前必须登录” | 用例模型的学生角色、登录用例、预约用例 |
| “同一时间段不能重复预约” | 活动图分支、领域概念模型约束、测试用例 |
| “管理员维护座位” | 管理员角色、座位管理用例、后台页面原型 |
| “发送预约通知” | 组件关系、代码服务模块、说明书接口描述 |

## 常见问题与处理

- AI 修复失败：保留原规则，手动补齐角色、触发条件、输入输出和异常处理后重试。
- 规则确认后又修改需求：平台会提示需求已修改，需要重新生成或确认规则。
- 生成可行性分析或需求模型被阻止：通常是没有已接受规则、仍有待确认修复项或质量提示未处理。
- 规则太泛：把“系统要好用”改成可验证的业务规则，例如“预约提交失败时保留用户输入并显示原因”。
