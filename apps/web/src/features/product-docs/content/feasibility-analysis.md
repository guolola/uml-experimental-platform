# 可行性分析：系统上下文图（系统环境图）、实现方案与研究报告

## 适用场景

需求规则已经确认，你需要在进入需求模型和设计阶段前，明确系统边界、比较可实施方案，并形成可追踪的可行性研究结论。

## 入口位置

- 项目工作台左侧“可行性分析”。
- 说明书页“可行性研究报告”模板的“前往可行性分析”入口。
- 运行历史中的可行性分析任务和可行性研究报告记录。

![可行性分析产物概览](/help/images/docs-feasibility.png)

## 前置条件

| 检查项 | 正常状态 |
| --- | --- |
| 系统需求 | 至少有一条已接受的需求规则 |
| Provider 与模型 | 已选择当前账号或项目可用的 Provider 和模型 |
| 项目权限 | 当前角色可以更新工作区并启动生成任务 |
| 补充资料 | 可留空；预算、周期、人员等真实事实建议先填写 |

## 生成系统上下文图（系统环境图）

1. 选择“系统上下文图（系统环境图）”；如果还没有当前有效的该图，选择“实现方案”时系统会自动同时选择该图。
2. 点击“一键生成全部”或单独生成系统上下文图（系统环境图）。
3. 在模型详情中检查中心系统、人员、外部系统、高层交互和来源规则。
4. 手动编辑元素或关系后保存；结构化模型、追踪矩阵、PlantUML 和 SVG 会一起校验并更新。

![上下文模型及追踪详情](/help/images/docs-feasibility-context.png)

## 生成并确认实现方案

实现方案基于当前需求规则、系统上下文图（系统环境图）和补充事实生成。首次完整结果包含两个候选方案，并明确推荐方案和选择依据。

1. 比较候选方案的成本、周期、优势和约束。
2. 分别查看每个方案的架构、模块、集成、数据、部署与安全策略。
3. 检查里程碑、责任角色、依赖和验收条件。
4. 核对成本与收益区间、分析周期、风险登记表和风险矩阵。
5. 检查技术、运行、进度、经济和法律五类结论。
6. 编辑后先“应用”到本地草稿，再点击页头“保存方案”完成持久化。

![候选方案与实现方案工作区](/help/images/docs-feasibility-plan.png)

## 产物有效性与重新生成

| 状态 | 原因 | 处理方式 |
| --- | --- | --- |
| 当前有效 | 来源规则、上下文和补充事实未变化 | 可以生成可行性研究报告 |
| 系统上下文图（系统环境图）已过时 | 已接受规则发生变化 | 重新生成系统上下文图（系统环境图）和实现方案 |
| 实现方案已过时 | 当前上下文或补充事实发生变化 | 保留当前上下文，仅重新生成实现方案 |
| 有未保存修改 | 编辑内容仍在本地草稿 | 保存方案，或确认放弃后重新生成 |

重新生成会覆盖对应产物的未保存修改。页面出现确认提示时，应先决定保存还是放弃草稿。

## 生成可行性研究报告

打开说明书页并选择“可行性研究报告”。报告只要求当前有效的系统上下文图（系统环境图）和实现方案，不依赖需求 UML 或设计模型。若产物缺失或过时，模板会显示具体原因，并带你回到可行性分析页且自动选择需要重建的产物。

![三类说明书模板与可行性报告状态](/help/images/docs-documents.png)

## 预期输出

| 输出 | 主要内容 |
| --- | --- |
| 系统上下文图（系统环境图） | 系统边界、外部参与者、交互、PlantUML、SVG、规则追踪 |
| 实现方案 | 候选方案、推荐依据、技术方案、实施计划、成本收益、风险、五类结论 |
| 可行性研究报告 | 封面资料、分析依据、系统上下文图（系统环境图）、推荐方案和结论的 DOCX 版本 |
| 运行证据 | 生成阶段、模型、错误、快照和报告文件状态 |

## 常见问题与处理

- 生成按钮不可用：先确认系统需求页已有接受规则、Provider 可用且当前角色有生成权限。
- 成本金额不可信：未确认金额会标记为 AI 估算；应填写真实事实或手动修改并保存。
- 候选方案没有独立详情：旧工作区或新增候选项需要重新生成实现方案。
- 报告按钮不可用：按模板附近提示重新生成过期的系统上下文图（系统环境图）或实现方案。
- 修改规则后报告失效：这是预期的产物新鲜度门禁，避免旧结论继续作为当前报告依据。
