# 需求质量、基线与待确认项

## 适用场景

你看到“需求已修改”“请先确认需求规则修复结果”或“质量提示未处理”，需要知道为什么下游生成被阻止。

## 入口位置

系统需求页规则区域、质量提示区域和生成按钮附近。

![需求质量与基线截图](/help/images/docs-requirement-quality-baseline.png)

## 前置条件

已经生成过需求规则，或至少修改过需求文本。

## 操作步骤

1. 查看需求规则是否和当前文本一致。
2. 查看质量提示是否还有待处理项。
3. 对 AI 修复候选选择采纳或忽略。
4. 确认后再生成 UML。
5. 如果需求文本改动较大，重新生成规则。

## 输入示例

```text
待确认项：规则 R-03 缺少失败处理。
AI 修复建议：预约失败时保留用户选择并提示失败原因。
```

## 预期输出

| 状态 | 含义 |
| --- | --- |
| 已确认 | 可作为下游生成输入 |
| 待确认 | 需要人工决定是否采纳 |
| 已修改 | 文本变化后规则可能过期 |
| 阻塞 | 下游生成暂时不可执行 |

## 映射关系

需求基线会被需求 UML、设计模型、测试用例和说明书共同引用。若基线过期，下游产物可能与最新需求不一致。

## 常见问题与处理

- 为什么要确认修复：避免 AI 自动改需求后直接影响所有下游。
- 能不能忽略质量提示：可以，但要理解下游可能缺图、缺测试或说明书表述不完整。
- 为什么重新生成规则：需求文本改变后，旧规则不再可靠。
