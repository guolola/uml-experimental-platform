# 设计模型生成与设计详情

## 适用场景

你已经生成需求 UML，准备推导设计阶段产物，并检查设计图是否能支撑代码原型和设计说明书。

## 入口位置

工作台左侧“设计模型”，以及侧边栏设计模型分组下的具体设计产物。

![设计模型截图](/help/images/docs-design-overview.png)

## 前置条件

需求模型至少有用例模型和领域概念模型。用例实现设计依赖用例事件流。

## 操作步骤

1. 打开设计模型页。
2. 选择需要生成的设计模型。
3. 点击生成设计模型。
4. 在侧边栏打开总体架构图、用例实现设计、设计类图、界面关系图、数据库设计等。
5. 查看设计元素、关系、源码和渲染状态。

## 输入示例

| 输入 | 示例 |
| --- | --- |
| 上游用例 | 学生预约座位 |
| 上游实体 | Student、Seat、Reservation |
| 设计目标 | React 原型、设计说明书、测试用例 |

## 7 类设计模型

| 模型 | 用途 | 示例 |
| --- | --- | --- |
| 总体架构图 | 子系统、包、核心组件 | Web、API、Domain、Infra |
| 用例实现设计 | 事件流到对象调用 | 提交预约时序 |
| 设计类图 | 服务、实体、接口、聚合 | ReservationService |
| 界面关系图 | 页面状态和跳转 | 查询页 -> 预约确认页 |
| 数据库设计 | 表、主键、外键 | reservations、seats |
| 组件关系 | 组件接口和依赖 | NotificationService |
| 部署设计 | 组件部署拓扑 | Web Pod、API Pod、DB |

## 预期输出

设计模型页输出结构化设计模型、Design PlantUML、Design SVG 和设计追踪关系。代码页和说明书页会读取这些产物。

## 映射关系

| 需求模型 | 设计模型 |
| --- | --- |
| 用例模型 | 用例实现设计、界面关系 |
| 领域概念模型 | 设计类图、数据库设计 |
| 总体业务流程 | 组件关系、架构图 |
| 部署需求模型 | 部署设计 |

## 常见问题与处理

- 设计生成失败：先看生成任务的设计阶段子任务。
- 用例实现设计缺少某个用例：检查需求用例模型是否包含该用例。
- 设计图看不懂：先看元素列表，再看图。
