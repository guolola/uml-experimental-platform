# 测试用例与覆盖关系

## 适用场景

你需要根据需求和设计生成测试用例，检查每条关键规则是否有测试覆盖。

## 入口位置

工作台左侧“测试”。

![测试用例截图](/help/images/docs-testing.png)

## 前置条件

至少需要需求规则和用例模型。设计模型越完整，测试步骤和预期结果越具体。

## 操作步骤

1. 打开测试页。
2. 查看前置条件提示，确认用例模型和设计模型是否可用。
3. 点击生成测试用例。
4. 按测试场景筛选，例如正常预约、重复预约、管理员维护。
5. 检查每条测试用例关联的需求规则和设计元素。

## 输入示例

| 需求规则 | 可能测试 |
| --- | --- |
| 学生不能重复预约同一时间段 | 重复提交时显示错误且不创建记录 |
| 预约成功后发送通知 | 成功预约后展示通知记录 |

## 预期输出

| 输出 | 说明 |
| --- | --- |
| 测试用例 | 前置条件、步骤、输入、预期结果 |
| 覆盖关系 | 需求规则和测试用例的映射 |
| 场景筛选 | 快速定位某类业务流程 |

## 映射关系

测试用例来自需求规则和设计模型。需求规则提供“测什么”，设计模型提供“怎么走流程”，代码原型用于人工验证页面是否符合预期。

## 常见问题与处理

- 无法生成测试：先生成用例模型和设计模型。
- 测试太泛：补充需求中的边界条件和异常分支。
- 某条规则无测试：回到需求页明确可验证条件后重新生成。
