# 需求到设计的追踪链路

## 适用场景

你已经生成需求模型和设计模型，需要证明每条需求是否被设计覆盖，并定位低置信或待复核的映射。

## 入口位置

- 设计页中的追踪矩阵入口。
- 工作台侧边栏设计模型旁的“跟踪矩阵”。
- 顶部栏“链路图”查看跨阶段关系。

![设计追踪矩阵截图](/help/images/docs-design-traceability.png)

## 前置条件

至少有需求 UML 和设计模型。用例实现设计依赖用例模型和事件流，设计类图、界面关系和数据库设计依赖需求模型结构。

## 操作步骤

1. 打开设计页，确认设计模型已生成。
2. 进入“设计追踪矩阵”，按需求元素查看目标设计元素。
3. 对低置信关系进行人工复核。
4. 打开链路图，检查需求 -> 设计 -> 代码/测试/说明书是否连续。
5. 若缺少设计覆盖，回到设计页重新生成或补充需求。

## 输入示例

需求规则：“预约提交前必须校验学生身份、座位可用性和重复预约。”

## 预期输出

| 输出 | 说明 |
| --- | --- |
| 设计追踪矩阵 | 每个需求元素对应哪些设计元素 |
| 上游设计引用 | 某个设计元素依赖哪些需求模型或用例实现 |
| 链路图 | 跨阶段查看需求、模型、代码、测试和说明书证据 |
| 待复核项 | 低置信映射，需要人工确认 |

## 映射关系

| 需求元素 | 设计目标 |
| --- | --- |
| Reservation 用例 | 预约用例实现设计 |
| Student、Seat、Reservation 实体 | 设计类图中的实体、服务和仓储 |
| 预约成功通知 | 组件关系中的 NotificationService |
| 重复预约限制 | 数据库唯一约束和服务校验逻辑 |

## 常见问题与处理

- 追踪矩阵为空：先确认设计模型是否生成成功。
- 映射看起来不准确：查看低置信提示，必要时调整需求规则后重新生成。
- 链路断开：找到断点页面，例如需求模型缺失、设计失败或代码未生成。
- 说明书缺少追踪关系：先补齐追踪矩阵，再重新生成说明书。
