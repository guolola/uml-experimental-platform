# 快速开始

## 适用场景

你第一次使用平台，想用一个“图书馆预约系统”案例跑通从项目、系统需求、可行性分析到说明书的完整链路。这个页面不解释所有按钮细节，只告诉你每一步去哪里、产出什么、下一步依赖什么。

## 入口位置

- 顶部导航：进入[项目首页](/projects)。
- 项目卡片：打开“图书馆预约系统”项目。
- 工作台左侧：依次进入系统需求、可行性分析、需求模型、图、设计模型、代码、测试、说明书。
- 项目顶部：打开生成任务、运行历史、链路图和项目抽屉。

## 前置条件

| 检查项 | 看哪里 | 正常状态 |
| --- | --- | --- |
| 是否已登录 | 顶部账号入口 | 能看到账号和退出入口 |
| 是否有项目 | 项目首页 | 至少有一个可进入的项目 |
| 模型是否可用 | 顶部账号入口 -> 全局设置，或项目设置 | 已选择托管 Provider 和默认模型 |
| 是否有运行中任务 | 项目顶部生成任务 | 没有阻塞中的失败任务 |

## 操作步骤

1. 在项目首页新建或进入“图书馆预约系统”。
2. 在系统需求页粘贴需求文本，先生成需求规则。
3. 处理质量提示和 AI 修复建议，确认规则。
4. 进入可行性分析，生成并检查系统上下文图（系统环境图）和实现方案；补充预算、周期或人员事实后保存当前方案。
5. 进入需求模型生成 UML，查看用例模型、领域概念模型、总体业务流程等图表。
6. 打开模型详情页，检查元素列表、PlantUML、SVG 和追踪矩阵。
7. 进入设计模型，生成总体架构、用例实现设计、设计类图、界面关系和数据库设计。
8. 进入代码页生成 React 原型，再进入测试页生成测试用例。
9. 进入说明书页，按产物状态生成需求规格说明书、软件设计说明书或可行性研究报告。
10. 用运行历史复盘每一次生成，必要时恢复快照。

## 输入示例

```text
图书馆预约系统允许学生登录后查询空闲座位，选择日期和时间段提交预约。
系统需要防止同一学生同一时间段重复预约，并在预约成功后发送通知。
管理员可以维护座位、查看预约记录，并处理异常取消。
```

## 预期输出

| 阶段 | 主要输出 | 下一步使用 |
| --- | --- | --- |
| 系统需求 | 需求规则、质量提示、需求基线 | 生成可行性分析、需求模型和说明书 |
| 可行性分析 | 系统上下文图（系统环境图）、候选实现方案、成本收益、风险和五类结论 | 形成实施决策和可行性研究报告 |
| UML | 7 类需求模型、PlantUML、SVG、追踪矩阵 | 生成设计模型 |
| 设计 | 7 类设计模型、设计追踪矩阵 | 生成代码和说明书 |
| 代码 | React 文件树、预览、质量诊断 | 验证页面流程 |
| 测试 | 测试用例、覆盖关系 | 检查需求是否被测试覆盖 |

## 映射关系

每一步都要能回答“这个结果来自哪里”：

| 来源 | 映射到 | 在哪里看 |
| --- | --- | --- |
| 需求文本 | 需求规则 | 系统需求页规则列表 |
| 需求规则 | 系统上下文图（系统环境图）与实现方案 | 可行性分析、可行性研究报告 |
| 需求规则 | 需求 UML 元素 | 模型详情页、追踪矩阵 |
| 需求 UML | 设计模型 | 设计追踪矩阵、链路图 |
| 设计模型 | 代码页面与组件 | 代码页文件树、质量诊断 |
| 需求和设计 | 测试用例 | 测试页覆盖关系 |
| 全部产物 | 说明书和运行证据 | 说明书页、运行历史 |

## 常见问题与处理

- 生成按钮不能点：先看按钮附近的阻塞原因，通常是需求规则未确认、前置产物缺失、Provider 不可用、权限不足或任务正在运行。
- 生成失败：打开项目顶部“生成任务”，查看失败阶段和是否可以重试。
- 图表为空：打开模型详情页，确认结构化模型、PlantUML 和 SVG 哪一步缺失。
- 可行性研究报告不可生成：回到可行性分析，按提示重建过期的系统上下文图（系统环境图）或实现方案。
- 说明书缺图：先回到图或设计页面，补齐成功渲染的 SVG。
