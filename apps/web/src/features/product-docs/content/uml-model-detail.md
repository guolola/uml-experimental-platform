# 模型详情页、元素列表与追踪矩阵

## 适用场景

你不只想看 UML 图片，还要检查模型元素、关系、图源码、手动重绘和每个元素的需求来源。

## 入口位置

- 工作台侧边栏“图”分组打开具体模型。
- 图表页点击元素、列表项或“跟踪矩阵”。

![模型详情页截图](/help/images/docs-uml-model-detail.png)

## 前置条件

对应 UML 模型已经生成。若只有结构化模型没有 SVG，仍可以看元素列表和 PlantUML。

## 操作步骤

1. 打开用例模型或领域概念模型。
2. 切换图表、模型、源码和追踪视图。
3. 使用元素类型筛选，例如 Actor、UseCase、Class、Relation。
4. 点击元素查看详情。
5. 图不准确时使用手动重绘或重新生成。
6. 打开追踪矩阵确认需求规则是否覆盖。

## 输入示例

元素：“提交预约”用例。

## 预期输出

| 区域 | 说明 |
| --- | --- |
| 图表 | SVG 渲染结果 |
| 元素列表 | 结构化模型中的元素和关系 |
| PlantUML | 可渲染图源码 |
| 追踪矩阵 | 需求规则到模型元素的映射 |
| 手动重绘状态 | 标记模型是否被人工调整 |

## 映射关系

| 模型详情项 | 来自 | 用于 |
| --- | --- | --- |
| Actor 学生 | 需求角色描述 | 用例模型、测试角色 |
| UseCase 提交预约 | 功能需求 | 设计时序、代码页面 |
| Reservation 类 | 数据需求 | 设计类图、数据库设计 |
| PlantUML | 结构化模型 | SVG 和说明书嵌图 |

## 常见问题与处理

- 元素列表有但图没有：PlantUML 或 SVG 渲染失败。
- 追踪矩阵缺项：需求规则可能太泛，或模型生成未覆盖。
- 手动重绘后不一致：查看手动修改提示，必要时重新生成下游设计。
