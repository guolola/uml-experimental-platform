# 用户体系与后台管理系统页面规划

## Summary

后台管理系统另起 Git 仓库，只做管理端前端；用户、项目、权限、运行记录、文档、模型供应商、安全审计等核心能力仍放在当前主项目 API 中。当前核心 v1 已按“身份 + 项目归属 + 权限校验 + PostgreSQL 持久化 + Provider 托管 + 审计 + 后台真实 API”推进，生产业务功能必须登录后使用，后台默认消费主项目真实 API。

本文件是用户体系与后台管理系统的唯一主规格。后续主项目实现、后台管理仓库实现、子代理任务拆分，都必须优先引用本文件。

## 当前项目用户侧入口

### 登录页 `/login`

- 账号密码登录。
- 登录失败提示。
- 邮箱未验证提示。
- MFA 验证入口。
- 找回密码入口。
- 会话建议使用 `HttpOnly + Secure + SameSite` Cookie。
- 不把 token 放进 `localStorage`。

### 注册 / 邮箱验证页 `/register`、`/verify-email`

- 支持开放注册或邀请码注册。
- 邮箱验证。
- 密码强度提示。
- 服务条款确认。
- 验证过期和重发状态。
- 学校或课程场景优先设计“管理员邀请注册”。

### 找回 / 重置密码页 `/forgot-password`、`/reset-password`

- 发送重置邮件。
- 校验短期 token。
- 新密码强度提示。
- 重置后强制旧会话失效。

### 项目首页 `/projects`

- 展示我的项目、团队项目、最近打开、最近生成、归档项目。
- 支持搜索、筛选、新建项目。
- 生产功能必须登录后使用；未登录用户只能访问官网首页和认证页。
- 不提供匿名工作台给未登录用户作为当前产品入口。

### 项目创建页 `/projects/new`

- 项目名称。
- 项目描述。
- 课程/班级标签。
- 项目模板。
- 可见性。
- 默认模型策略。
- 课程、班级、团队和默认托管 Provider 绑定。
- 历史匿名数据迁移不作为当前 v1 功能入口；如保留底层 legacy 工具，仅限 dev/test 或后续独立迁移流程。

### 项目工作台 `/projects/:projectId`

- 承接当前“需求 / 图 / 设计 / 代码 / 说明书”主工作台。
- 所有数据绑定 `projectId` 和当前用户权限。
- 显示项目成员。
- 显示运行中任务。
- 显示自动保存状态。

### 项目设置 `/projects/:projectId/settings`

- 项目信息。
- 归档项目。
- 删除项目。
- 数据导出。
- 默认模型策略。
- 数据保留策略。
- 删除和导出需要二次确认。

### 项目成员与权限 `/projects/:projectId/members`

- 邀请成员。
- 角色分配。
- 移除成员。
- 邀请过期状态。
- 权限不足状态。
- 角色至少包括所有者、编辑者、查看者。

### 运行历史 `/projects/:projectId/history`

- 替代当前本地历史抽屉。
- 按阶段、状态、模型、操作者、时间筛选。
- 支持恢复快照。
- 支持导出报告。
- 支持查看错误。
- 支持重新运行。

### 文档中心 `/projects/:projectId/documents`

- 管理需求规格说明书。
- 管理软件设计说明书。
- 展示 OnlyOffice 编辑状态。
- 展示版本记录。
- 支持下载、重命名、删除。

### 右上角账号弹窗

- 个人资料。
- 邮箱。
- 头像。
- MFA 状态。
- 修改密码。
- 活跃会话。
- 退出所有设备。
- 最近登录记录。
- 异常登录提醒。

### 右上角设置弹窗

- 模型 tab：选择托管 Provider Config 和默认模型。
- 模型 tab：测试托管配置，密钥只显示掩码。
- 偏好 tab：字号主题、自动生成、旧结果提示等普通偏好。
- 登录态只保存 `providerConfigId + defaultModel`，不保存明文 `apiKey` 或任意 `apiBaseUrl` 作为生成主路径。
- 明文 Provider legacy 表单仅允许在 dev/test 显式开关下用于底层兼容，不作为生产产品入口。
- 通知偏好。
- 字号主题等普通偏好。

- 风险事件。

## 主项目必须补的 API / 数据能力

- 新增用户、组织、成员、角色、权限、会话、MFA、登录日志模型。
- 新增项目/工作区模型，把所有生产业务数据绑定到实名项目归属。
- 将 run record 从内存 `Map` 持久化，记录 `userId`、`projectId`、状态、阶段、模型、耗时、错误、产物引用、成本估算。
- 所有 run snapshot、SSE、文档下载、OnlyOffice 配置都必须校验当前用户是否有项目权限，不能只凭 `runId` 或 `documentId`。
- 模型供应商改为后端配置中心：Base URL allowlist、密钥加密保存、密钥不回显、用户/组织配额、失败熔断。
- 增加后台接口：
  - `/api/admin/metrics`
  - `/api/admin/users`
  - `/api/admin/projects`
  - `/api/admin/runs`
  - `/api/admin/documents`
  - `/api/admin/provider-configs`
  - `/api/admin/audit-logs`
  - `/api/admin/risk-events`
  - `/api/admin/rate-limits`
  - `/api/admin/system/health`

## Security Defaults

- 禁止用前端传入的任意 `apiBaseUrl` 直接发请求，防 SSRF；只允许后台配置过的供应商域名。
- API Key 永不明文展示；新增后只显示尾号、用途、创建人、最近使用时间和风险状态。
- OnlyOffice callback URL、文件 URL、签名 token 必须限制来源、过期时间、文件大小和访问权限。
- SSE 事件流也要走身份校验和 CORS allowlist。
- 所有高危动作记录审计：权限变更、项目删除、文档下载、密钥轮换、任务取消/重试、功能开关、风控白名单。
- 限流按用户、项目、组织、IP、任务类型、模型供应商多层设计，防止刷生成、刷下载和刷模型测试。

## Test And Acceptance

- 未登录用户不能访问任何项目、run snapshot、SSE、文档下载。
- 未登录用户不能访问 `/projects`、`/workspace`、`/exam`、`/tutorial`、`/about` 等业务功能页；应回到官网首页或认证流程。
- A 用户不能通过猜测 `runId` 或 `documentId` 访问 B 用户项目数据。
- 管理员只能在自己的角色和数据范围内查看/操作。
- API Key 页面无法读回明文，轮换/吊销后旧密钥不可用。
- Provider Base URL 不在白名单时无法测试或生成。
- 所有后台高危操作都能在审计日志中查到操作者、目标、时间、IP、结果。
- 运行历史服务端化后，项目切换、恢复快照、删除历史都有明确确认和权限校验。

## Assumptions

- 后台管理系统前端单独建仓库，推荐使用同一套设计语言但不放进当前 monorepo。
- 主 API 继续作为唯一业务后端，后台通过新增 admin endpoints 访问。
- v1 优先做账号、项目、运行记录、文档、模型配置、安全审计，不做复杂费用对账。
- 生产环境未登录用户只能访问官网首页和认证页；匿名/legacy 能力仅限 dev/test 或底层兼容，不作为产品功能。
